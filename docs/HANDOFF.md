## How things work (the parts a new session needs)
- **Auth** is Better Auth 1.7 with the Drizzle adapter (`src/lib/auth/auth.ts`). `src/lib/db/schema/auth.ts` was generated by `npx @better-auth/cli@latest generate --config src/lib/auth/auth.ts --output src/lib/db/schema/auth.ts`; regenerate it after adding a plugin or a user field, then `npm run db:generate -- --name <what>` and `npm run db:migrate`. Ids are UUIDs generated by PostgreSQL.
- **Every credential form** is a client component with `useActionState` posting to `src/lib/auth/actions.ts` (a `"use server"` module: it may export only async functions; constants live in `src/lib/auth/constants.ts`). Errors are message keys under `authErrors`; dynamic keys are declared with `// i18n-keys:` comments so the catalogue check counts them as used.
- **Two Better Auth endpoints re-issue the session** (new cookie, old session deleted): `changePassword` and `verifyTOTP` during setup. A server action that calls them must end with `redirect(...)`; returning state makes Next re-render with the old cookie and the member lands on sign-in. The recovery codes after setup are shown through the `gr_2fa_setup` marker cookie (2 minutes) and `auth.api.viewBackupCodes` (server-only); the "Spremio sam kodove" button clears the marker.
- **Lockout** (`src/lib/auth/lockout.ts`): a before hook (refuse while locked) and an after hook (count or clear) on `/sign-in/email`; Better Auth's rate limiter (database storage) sits in front. Keys are keyed SHA-256 hashes of `email|ip`; the IP comes from `IP_HEADERS` (empty locally → "local"; set `x-forwarded-for` on Render).
- **The policy module** (`src/lib/authz/policy.ts`) is pure. Phase 5's data layer loads `Viewer`, `Owner`, `Graph` and facts, then calls `canViewProfileSection`, `canViewContent`, `canViewConversation`, `canViewPlaylist`, `canViewStaffObject`, `canInteract`. Staff "through a case" decisions return `mode: "case"` only when `ctx.caseId` is given; the caller logs the access.
- **Admin pages** live under `src/app/[locale]/(app)/admin/`; the layout calls `requireRole("editor", "moderator", "admin")`, which also demands `twoFactorEnabled`. Seeded staff accounts see the "turn on two-step verification" notice until they enable it.
- **Messages:** `messages/hr.json` and `messages/en.json` must have the same keys; `scripts/i18n-check.mjs` also flags unused keys and understands binding names other than `t` (`const tl = await getTranslations("…")`).
- **Tokens:** edit `design/tokens/tokens.json`, run `npm run tokens`; `src/styles/tokens.css` holds the `--gr-*` variables and a Tailwind `@theme` block (colour names shortened: `bg-canvas`, `text-fg-secondary`, `text-coral`). `src/styles/components.css` ports the Phase 3 component CSS (class names match `docs/design/components.md`).
- **Tests:** `npm run test` (unit, no database), `npm run test:db` (needs PostgreSQL; touches only its own rows, never the seeded flags), `npm run test:e2e` (Playwright reuses a running dev server; CI builds and serves). The e2e suite reads security email from `.mail-outbox.jsonl` (`EMAIL_TRANSPORT=file`), creates fresh `@example.test` accounts per run and computes TOTP codes itself (`tests/e2e/helpers.ts`).
- **CI** (`.github/workflows/ci.yml`): checks (format, lint, typecheck, tokens, i18n, unit, `npm audit --omit=dev --audit-level=high`), database (migrations current, migrate, seed, db tests), e2e (build, Playwright chromium with axe-core). The env values in the workflow are placeholders for the CI database only.

## Lessons (session 22)
- **Never edit UTF-8 files with PowerShell `Get-Content`/`Set-Content`:** Windows PowerShell 5.1 decodes as the ANSI code page and writes a BOM, which double-encoded `messages/*.json` (č → "ÄŤ") and broke `package.json` for Turbopack. Use the Write/Edit tools or Node; strip a BOM with `[System.IO.File]::ReadAllBytes`. ASCII-only files (`.env.example`, test setup) survive `-Encoding ascii`.
- `localhost` resolves to `::1` on this machine while the container publishes on `127.0.0.1` only: every local `DATABASE_URL` uses `127.0.0.1`.
- The Claude PostToolUse hook typechecks after every edit, so a batch of new files produces transient errors until the last file lands; they clear on their own.
- A `"use server"` file may export only async functions (constants and re-exports break the build).
- `@node-rs/argon2` is native: nothing imported by a client component may import it (hence `password-policy.ts`).
- The HIBP plugin shipped with Better Auth fails closed; the project's own plugin (`breached.ts`) fails open per D-054.
- Better Auth recovery codes are mixed-case by default; the project generates lower-case codes so phone keyboards do not break them.
- `next-intl`'s middleware forwards the request headers it was given: set `x-nonce` and the CSP on `request.headers` in place before calling it (wrapping the request in a new `Request` returned 404s).
- Playwright: scope `getByRole("alert")` to `main` (the Next.js dev overlay adds its own) and wait for the sign-in action's redirect before the next `goto` (the `signIn` helper does); the lockout test must create its own account because lock stages outlive a rerun.
- `npm overrides` for nested dependencies only apply after a clean install (`rm node_modules package-lock.json`).
- **Start the dev server from PowerShell, not from the Bash tool:** a server started with `( VAR=1 npx next dev & )` in Git Bash did not receive the inline variables (`E2E_EMAIL_FILE` was missing while `.env.local` keys were there). `$env:X="1"; Start-Process cmd "/c npx next dev"` works and the server can be checked with a throwaway route.
- **Deleting a route directory while `next dev` runs** left Turbopack in a reload loop (`reloadPage: HMR hash mismatch` every 200 ms on every page). Stop the server, delete `.next`, start again.
- `next build` evaluates the auth module with `NODE_ENV=production`; start-up-only guards must skip `NEXT_PHASE=phase-production-build`.
- Playwright against the production server (CI mode) runs with `CI=1 PORT=3100 APP_URL=http://localhost:3100 PLAYWRIGHT_BASE_URL=http://localhost:3100` after `npm run build`; the tests must not hard-code the port.
- **CI values must satisfy the production guards** (`src/lib/env.ts`): `next start` runs with `NODE_ENV=production`, so the workflow's `BETTER_AUTH_SECRET` needs 43+ characters and the file mail transport needs `E2E_EMAIL_FILE=1`. A guard failure shows as a 500 on every page and "Timed out waiting 120000ms from config.webServer" in Playwright; the server's own output is now piped into the CI log (`webServer.stdout: "pipe"`). Reproduce locally with the exact CI values: `npm run build`, then `CI=1 PORT=3100 … npx playwright test`.
- The e2e suite needs `E2E_EMAIL_FILE=1` on the server (file mail transport in production mode and ×10 on the Better Auth limits) and a cleared `rate_limit` table between runs (`docker compose exec -T postgres psql -U grooverift -d grooverift -c "delete from rate_limit;"`).

## Review findings (session 22, end) and what was done
Two read-only subagent reviews ran on the finished foundation. Every finding was verified against the code and fixed in the closing commit unless listed under "left open".

**Security review (3 high, 6 medium, 7 low):**
- H1 Google linking trusted the provider without `email_verified` → `trustedProviders` removed; Better Auth now links only a Google-verified email (S-09).
- H2 Admin pages were guarded only by the layout, which Next.js can skip → every admin page runs `adminPageGate` itself (`src/components/admin/gate.tsx`, `staffGate` in `session.ts`).
- H3 Client IP: empty header list in production meant one shared rate-limit bucket and one shared lockout pair; the lockout and the limiter parsed the IP differently → `IP_HEADERS` required in production (`env.ts`), `TRUSTED_PROXIES` added, the lockout uses Better Auth's `getIP` (`requestIp`), documented in `.env.example` and the runbook.
- M1 D-061, the 18+ confirmation and the `sign_up` flag were enforced only in the server actions → `src/lib/auth/hooks.ts` enforces them on the public API routes too (plus the locale whitelist).
- M2 Session bearer tokens were rendered into the devices list → the page sees ids only; the action resolves the token server-side.
- M3 `void sendMail()` could crash the process in production → `sendMailInBackground` catches and audits; production refuses to start with a development transport (`env.ts`, skipped during `next build` through `NEXT_PHASE`).
- M4 Better Auth's own admin endpoints bypassed the staff second-factor rule and the audit log → only `/admin/set-role` and `/admin/has-permission` are open, both need a second factor, every admin call is audited (hooks.ts).
- M5 Pair counter TOCTOU → one atomic upsert decides the window and count (`lockout.ts`).
- M6 Recovery-code marker cookie was a constant → HMAC over the new session token with a 2-minute expiry (`constants.ts`).
- L1 "keep other devices" was ignored → `=== "on"`. L2 locale validated. L3 non-string email in the hook. L4 placeholder secret refused, 43+ chars in production. L5 unverified or banned sign-ins no longer count as guesses. L6 policy defaults to deny for reactions and media without the fact (tests updated). L7 the Claude hook no longer uses a shell.

**Accessibility review (3 must, 11 should, 7 nice):** all must and should items fixed: focus moves to the error summary or the first invalid field on every form (`useFormErrorFocus`), navigation focuses the new page's `h1` (`FocusOnNavigate`, Amber underline instead of the ring), the nested admin shell on `/admin/audit` is gone, an empty sign-in names the missing field, the error summary shows the focus ring, the language button keeps its visible code in its name without `lang`, devices buttons are named per device with real busy labels, the devices list revalidates after a revoke and focus goes to the section heading, the password field receives focus when a confirm form opens, admin errors are in-page alerts, the password meter's live region is always mounted, admin cells say Da/Ne/skriveno and every page has a title, the QR image has its own label, the Google form is no longer nested. Nice items done: no `aria-label` on the Alfa pill, no double-coded toggle (`aria-pressed` dropped), `aria-invalid` on the age checkbox, the audit link shows only to admins. Left for later: `aria-current` on the admin nav, a tiny 32 px link row height (passes 2.5.8), `dialog.tsx` unused until a flow needs it.

**Left open on purpose:** CSP `style-src 'unsafe-inline'` (D-089 (12), Phase 6), `report-to` for CSP, SHA-pinned GitHub actions, the Render client-IP header to confirm on the first deploy (runbook §1).
