## Lessons (session 28)
- **A client component must never import from `src/lib/data`, not even a constant:** the import pulls `pg` into the browser bundle ("Module not found: Can't resolve 'net'/'tls'") and Turbopack then answers 500 on every page, not only the one that imported it. Shared rules live in a pure module (`src/lib/profile/constants.ts`); the data layer re-exports them for its own callers. `import type` is fine.
- **A `never`-returning helper narrows only as a function declaration** (`export function notAvailable(): never`), not as an arrow const; otherwise TypeScript keeps the "not-available" branch alive after the call.
- `unaccent()` is STABLE, so it cannot sit in an index expression: wrap it in an IMMUTABLE SQL function that names the dictionary explicitly (`search_fold`, migration 0005). Both extensions are trusted, so the application role creates them; the Render database must allow `CREATE EXTENSION` for them too (check on the first deploy).
- Custom SQL (extensions, functions, indexes drizzle cannot express) is appended to the generated migration after a `--> statement-breakpoint`; `db:generate --name ci_check` still reports no drift because those objects are not in the schema.
- The i18n checker binds a translation variable per file: a nested component with its own `const t = await getTranslations("profile.counts")` is read as the file's first binding; declare such keys with `// i18n-keys:` (or use a different variable name throughout).
- Playwright `getByRole("button", { name: "Prati" })` matches by substring, case-insensitively: "Pratiš, povezani. Prestani pratiti" too. Use `exact: true` for string names.
- A visually hidden live region that repeats a visible message makes `getByText` ambiguous; assert on the visible element (`.req-done`).
- Members created in one e2e run share a timestamp in their usernames, so a trigram search for one of them finds the others; assert that the hidden one is absent, not that the list is empty.
- axe `target-size` flags a field that sits under the fixed phone tab bar at the moment of the check: scroll the page to its end (or the last control into view) before `expectNoAxeViolations` on long settings pages.
- **Stopping the process that owns port 3000 does not stop a hand-started dev server:** `next dev` is a tree (cmd → npx → cmd → next → `start-server.js` → Turbopack pool); killing one member lets the rest live and the port comes back within seconds. Then Playwright (`reuseExistingServer`) silently runs against that server (`.env.local`: console mail, production rate limits), and the mail tests, the sign-ups ("Spremam…" stuck at `/join/account`, 429) and whatever follows fail for no reason in the code. Stop the whole tree: `Get-CimInstance Win32_Process -Filter "Name = 'node.exe'" | Where-Object { $_.CommandLine -match 'GrooveRift\\node_modules\\next\\dist' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }`, wait five seconds, confirm with `netstat` **and** that no `next dev` command line is left. Session 28 lost two full e2e runs to this.
- The `rate_limit_bucket` table must be cleared like `rate_limit` between manual browser passes; `tests/e2e/global-setup.ts` does both for the suite.

## Lessons (session 27)

## How things work (the parts a new session needs)
- **Auth** is Better Auth 1.7 with the Drizzle adapter (`src/lib/auth/auth.ts`). `src/lib/db/schema/auth.ts` was generated by `npx @better-auth/cli@latest generate --config src/lib/auth/auth.ts --output src/lib/db/schema/auth.ts`; regenerate it after adding a plugin or a user field, then `npm run db:generate -- --name <what>` and `npm run db:migrate`. Ids are UUIDs generated by PostgreSQL.
- **Accounts come from invitations only (step 5.4):** `/invite/<token>` sets the `gr_invite` cookie and redirects to `/join`; the pre-account steps (18+, language, account) keep nothing on the server; `createAccountAction` calls `signUpEmail` (the hooks check the cookie, verify the account and accept the invitation) and then `signInEmail`; the post-account steps write through `src/lib/data/onboarding.ts` and move `profile.onboarding_step`; `memberPage` redirects to that step until `onboarded_at` is set. Admins create invitations at `/admin/invites`; in development the link is printed by the console mail transport.
- **Profiles (step 5.5):** `src/proxy.ts` rewrites `/@name` to `/[locale]/u/[name]`; `profileByUsername` returns one of `not-available` (404 through `notAvailable()`), `blocked-by-you` (the blocker's own view) or a projection with only the sections the policy allowed and the counts for the lists the viewer may see. Writes on the graph and the profile go through `src/lib/profile/actions.ts` (the member id from the session, the target id checked twice); the client pieces call them with `useTransition`, show a toast and `router.refresh()`. The search (`src/lib/data/people.ts`) filters in SQL and again through `peopleFor` (the policy).
- **Every credential form** is a client component with `useActionState` posting to `src/lib/auth/actions.ts`, `src/lib/onboarding/actions.ts` or `src/lib/profile/actions.ts` (`"use server"` modules: they may export only async functions; constants live in `src/lib/auth/constants.ts`, `src/lib/onboarding/constants.ts` and `src/lib/profile/constants.ts`). Errors are message keys under `authErrors`; dynamic keys are declared with `// i18n-keys:` comments so the catalogue check counts them as used.
- **Two Better Auth endpoints re-issue the session** (new cookie, old session deleted): `changePassword` and `verifyTOTP` during setup. ## Lessons (session 22)
- **Never edit UTF-8 files with PowerShell `Get-Content`/`Set-Content`:** Windows PowerShell 5.1 decodes as the ANSI code page and writes a BOM, which double-encoded `messages/*.json` (č → "ÄŤ") and broke `package.json` for Turbopack. Use the Write/Edit tools or Node; strip a BOM with `[System.IO.File]::ReadAllBytes`. ASCII-only files (`.env.example`, test setup) survive `-Encoding ascii`.
- `localhost` resolves to `::1` on this machine while the container publishes on `127.0.0.1` only: every local `DATABASE_URL` uses `127.0.0.1`.
- The Claude PostToolUse hook typechecks after every edit, so a batch of new files produces transient errors until the last file lands; they clear on their own.
- A `"use server"` file may export only async functions (constants and re-exports break the build).
- `@node-rs/argon2` is native: nothing imported by a client component may import it (hence `password-policy.ts`).
- The HIBP plugin shipped with Better Auth fails closed; the project's own plugin (`breached.ts`) fails open per D-054.
- Better Auth recovery codes are mixed-case by default; the project generates lower-case codes so phone keyboards do not break them.
- `next-intl`'s middleware forwards the request headers it was given: set `x-nonce` and the CSP on `request.headers` in place before calling it (wrapping the request in a new `Request` returned 404s).
- Playwright: scope `getByRole("alert")` to `main` (the Next.js dev overlay adds its own) and wait for the sign-in action's redirect before the next `goto` (the `signIn` helper does); the lockout test must create its own account because lock stages outlive a rerun.
- `npm overrides` for nested dependencies usually apply only after a clean install (`rm node_modules package-lock.json`); session 24's override applied on a plain `npm install` because the package was new.
- **Start the dev server from PowerShell, not from the Bash tool:** a server started with `( VAR=1 npx next dev & )` in Git Bash did not receive the inline variables. `$env:X="1"; Start-Process cmd "/c npx next dev"` works and the server can be checked with a throwaway route.
- **Deleting a route directory while `next dev` runs** left Turbopack in a reload loop. Stop the server, delete `.next`, start again.
- `next build` evaluates the auth module with `NODE_ENV=production`; start-up-only guards must skip `NEXT_PHASE=phase-production-build`.
- Playwright against the production server (CI mode) runs with `CI=1 PORT=3100 APP_URL=http://localhost:3100 PLAYWRIGHT_BASE_URL=http://localhost:3100` after `npm run build`; the tests must not hard-code the port.
- **CI values must satisfy the production guards** (`src/lib/env.ts`): `BETTER_AUTH_SECRET` needs 43+ characters and the file mail transport needs `E2E_EMAIL_FILE=1`. A guard failure shows as a 500 on every page and "Timed out waiting 120000ms from config.webServer" in Playwright; the server's own output is piped into the CI log.
- The e2e suite needs `E2E_EMAIL_FILE=1` on the server and a cleared `rate_limit` table between runs (`docker compose exec -T postgres psql -U grooverift -d grooverift -c "delete from rate_limit;"`).
