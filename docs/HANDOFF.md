## Lessons (session 27)
- **A late server-action call after a redirect breaks the page in dev:** the username step's debounced availability check could fire after the form had submitted and the router had moved on; Next answered "Failed to find Server Action", the client threw an unhandled rejection and later clicks on that page did nothing. Guard every background action call with a "submitted" ref, cancel it in the effect cleanup and catch its errors; never let a decorative check reject.
- **Better Auth database hooks get the endpoint context as their second argument** (`before(data, context)`): `context.getCookie(...)` and `context.path` are available, so a rule like "no account without an invitation cookie" lives in one place for every provider; a thrown `APIError` with a `code` inside the OAuth callback becomes `?error=<code>` on `errorCallbackURL`.
- `signUpEmail` always sends the verification mail when `sendOnSignUp` is on; skipping it for already verified users is done inside `sendVerificationEmail` (`if (user.emailVerified) return`), because the route does not check.
- `auth.api.signUpEmail` ignores unknown body fields in its TypeScript type: build the body as a `const` object first (the `age18` flag), as the old action did.
- The migrations test deletes the newest journal rows by count: keep `DOWN.length` in that query when a down file is added.
- `jsx-a11y/label-has-associated-control` wants the label's text within two levels of nesting: put the visible text directly in the label's child span, not three spans deep.
- `react-hooks/set-state-in-effect` rejects synchronous `setState` in an effect: derive from props and state in render (the results shown only for the query they answer), set state only inside the async callback, or use `useSyncExternalStore` for a client-only value such as the browser's time zone.
- The i18n checker reads `t("status")` as a leaf key; an object key under the same name (`status.sent`) needs a different header key (`statusHeading`) and a `const key = \`status.${s}\` as const` for the dynamic lookup.
- Two Playwright workers on one dev server make a full onboarding walk slow (1–2 min per long test); the timeout is 120 s now and the three longest tests are `test.slow()`. Timeouts show up as "element not found" at the last step, not as logic errors: read the time in the failure line first.
- `getByRole("link", { name: "Natrag" })` matches both the top-bar back icon (aria-label) and a "Natrag" button link: use `.last()` or a more specific name.
- **A production server from an earlier session can outlive it:** Playwright's CI-mode `next start -p 3100` from session 26 was still running (and serving the old build) when session 27 tried the production e2e; `netstat` did not list it, but `Get-CimInstance Win32_Process -Filter "Name = 'node.exe'"` showed the command line. Before `CI=1 PORT=3100 …`, check `curl -sI http://localhost:3100/` and stop a stale `next start` (never the other projects' node processes).
- **After "Odjavi se", wait for the redirect** (`await expect(page).toHaveURL(/\/$/)`) before the next `goto`: on the fast production server a `goto` straight after the click cancels the sign-out response and the session cookie survives, which showed up as the E3 page instead of E1 only in CI mode.

## How things work (the parts a new session needs)
- **Auth** is Better Auth 1.7 with the Drizzle adapter (`src/lib/auth/auth.ts`). `src/lib/db/schema/auth.ts` was generated by `npx @better-auth/cli@latest generate --config src/lib/auth/auth.ts --output src/lib/db/schema/auth.ts`; regenerate it after adding a plugin or a user field, then `npm run db:generate -- --name <what>` and `npm run db:migrate`. Ids are UUIDs generated by PostgreSQL.
- **Accounts come from invitations only (step 5.4):** `/invite/<token>` sets the `gr_invite` cookie and redirects to `/join`; the pre-account steps (18+, language, account) keep nothing on the server; `createAccountAction` calls `signUpEmail` (the hooks check the cookie, verify the account and accept the invitation) and then `signInEmail`; the post-account steps write through `src/lib/data/onboarding.ts` and move `profile.onboarding_step`; `memberPage` redirects to that step until `onboarded_at` is set. Admins create invitations at `/admin/invites`; in development the link is printed by the console mail transport.
- **Every credential form** is a client component with `useActionState` posting to `src/lib/auth/actions.ts` or `src/lib/onboarding/actions.ts` (`"use server"` modules: they may export only async functions; constants live in `src/lib/auth/constants.ts` and `src/lib/onboarding/constants.ts`). Errors are message keys under `authErrors`; dynamic keys are declared with `// i18n-keys:` comments so the catalogue check counts them as used.
- **Two Better Auth endpoints re-issue the session** (new cookie, old session deleted): `changePassword` and `verifyTOTP` during setup. A server action that calls them must end with `redirect(...)`; returning state makes Next re-render with the old cookie and the member lands on sign-in. The recovery codes after setup are shown through the `gr_2fa_setup` marker cookie (2 minutes) and `auth.api.viewBackupCodes` (server-only); the "Spremio sam kodove" button clears the marker.
- **Lockout** (`src/lib/auth/lockout.ts`): a before hook (refuse while locked) and an after hook (count or clear) on `/sign-in/email`; Better Auth's rate limiter (database storage) sits in front. Keys are keyed SHA-256 hashes of `email|ip`; the IP comes from `IP_HEADERS` (empty locally → "local"; set `x-forwarded-for` on Render).
- **The policy module** (`src/lib/authz/policy.ts`) is pure. Phase 5's data layer (step 5.2, `src/lib/data/`) loads `Viewer`, `Owner`, `Graph` and facts, then calls `canViewProfileSection`, `canViewContent`, `canViewConversation`, `canViewPlaylist`, `canViewStaffObject`, `canInteract`. Staff "through a case" decisions return `mode: "case"` only when `ctx.caseId` is given; the caller logs the access.
- **Admin pages** live under `src/app/[locale]/(app)/admin/`; every page runs `adminPageGate` itself (`requireRole("editor", "moderator", "admin")`, which also demands `twoFactorEnabled`). Seeded staff accounts see the "turn on two-step verification" notice until they enable it. `/admin/invites` is admin-only.
- **Messages:** `messages/hr.json` and `messages/en.json` must have the same keys; `scripts/i18n-check.mjs` also flags unused keys and understands binding names other than `t` (`const tl = await getTranslations("…")`).
- **Tokens:** edit `design/tokens/tokens.json`, run `npm run tokens`; `src/styles/tokens.css` holds the `--gr-*` variables and a Tailwind `@theme` block (colour names shortened: `bg-canvas`, `text-fg-secondary`, `text-coral`). `src/styles/components.css` ports the Phase 3 component CSS (class names match `docs/design/components.md`); `src/styles/onboarding.css` ports the onb pieces (progress, visibility rows, chips, "Kako radi", the reminder example, the "Spremno" facts).
- **Tests:** `npm run test` (unit, no database), `npm run test:db` (needs PostgreSQL; touches only its own rows, never the seeded flags), `npm run test:e2e` (Playwright reuses a running dev server; CI builds and serves). The e2e suite reads security email from `.mail-outbox.jsonl` (`EMAIL_TRANSPORT=file`), creates fresh `@example.test` accounts per run through real invitations (`tests/e2e/db.ts` inserts the rows) and computes TOTP codes itself (`tests/e2e/helpers.ts`).
- **Worker** (`src/worker.ts`): pg-boss on the same database, one housekeeping job today; 5.6 adds the publication job keyed by UTC date, 5.10 the export and purge jobs, 5.12 the reminder scheduler (the onboarding step already stores `daily_drop_reminder`).
- **CI** (`.github/workflows/ci.yml`): checks (format, lint, typecheck, tokens, i18n, unit, `npm audit --omit=dev --audit-level=high`), database (migrations current, migrate, seed, db tests), e2e (build, Playwright chromium with axe-core). ## Lessons (session 22)
- **Never edit UTF-8 files with PowerShell `Get-Content`/`Set-Content`:** Windows PowerShell 5.1 decodes as the ANSI code page and writes a BOM, which double-encoded `messages/*.json` (č → "ÄŤ") and broke `package.json` for Turbopack. Use the Write/Edit tools or Node; strip a BOM with `[System.IO.File]::ReadAllBytes`. ASCII-only files (`.env.example`, test setup) survive `-Encoding ascii`.
- `localhost` resolves to `::1` on this machine while the container publishes on `127.0.0.1` only: every local `DATABASE_URL` uses `127.0.0.1`.
- The Claude PostToolUse hook typechecks after every edit, so a batch of new files produces transient errors until the last file lands; they clear on their own.
- A `"use server"` file may export only async functions (constants and re-exports break the build).
- `@node-rs/argon2` is native: nothing imported by a client component may import it (hence `password-policy.ts`).
- The HIBP plugin shipped with Better Auth fails closed; the project's own plugin (`breached.ts`) fails open per D-054.
- Better Auth recovery codes are mixed-case by default; the project generates lower-case codes so phone keyboards do not break them.
- `next-intl`'s middleware forwards the request headers it was given: set `x-nonce` and the CSP on `request.headers` in place before calling it (wrapping the request in a new `Request` returned 404s).
- Playwright: scope `getByRole("alert")` to `main` (the Next.js dev overlay adds its own) and wait for the sign-in action's redirect before the next `goto` (the `signIn` helper does); the lockout test must create its own account because lock stages outlive a rerun.
- `npm overrides` for nested dependencies usually apply only after a clean install (`rm node_modules package-lock.json`); session 24's override applied on a plain `npm install` because the package was new.
- **Start the dev server from PowerShell, not from the Bash tool:** a server started with `( VAR=1 npx next dev & )` in Git Bash did not receive the inline variables. `$env:X="1"; Start-Process cmd "/c npx next dev"` works and the server can be checked with a throwaway route.
- **Deleting a route directory while `next dev` runs** left Turbopack in a reload loop. Stop the server, delete `.next`, start again.
- `next build` evaluates the auth module with `NODE_ENV=production`; start-up-only guards must skip `NEXT_PHASE=phase-production-build`.
- Playwright against the production server (CI mode) runs with `CI=1 PORT=3100 APP_URL=http://localhost:3100 PLAYWRIGHT_BASE_URL=http://localhost:3100` after `npm run build`; the tests must not hard-code the port.
- **CI values must satisfy the production guards** (`src/lib/env.ts`): `BETTER_AUTH_SECRET` needs 43+ characters and the file mail transport needs `E2E_EMAIL_FILE=1`. A guard failure shows as a 500 on every page and "Timed out waiting 120000ms from config.webServer" in Playwright; the server's own output is piped into the CI log.
- The e2e suite needs `E2E_EMAIL_FILE=1` on the server and a cleared `rate_limit` table between runs (`docker compose exec -T postgres psql -U grooverift -d grooverift -c "delete from rate_limit;"`).
